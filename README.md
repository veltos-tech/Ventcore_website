# VentCore — сайт

Next.js 16 (App Router, Turbopack) · React 19 · TypeScript · Tailwind CSS 4 — стек из ТЗ (краткая версия ТЗ и макеты Figma хранятся вне репозитория).

## Запуск

```bash
npm install
npm run dev        # http://localhost:3000
npm run build      # продакшен-сборка
npm run start
npm run lint       # ESLint (конфиг Next)
npm run typecheck  # tsc --noEmit
```

Переменные окружения — в `.env.example` (скопировать в `.env.local`).

## Структура


## Дизайн-система

Токены — в `src/app/globals.css`, блок `@theme`:

| Токен | Значение | Утилиты |
|---|---|---|
| `--color-navy` | `#062647` | `text-navy`, `bg-navy` |
| `--color-blue` | `#0377C9` | `bg-blue`, кнопки, акценты |
| `--color-muted` | `#8292A2` | рубрики секций, рамки карточек |
| `--color-line` | `#ADB8C3` | разделители |
| `--font-display` / `--font-sans` | Manrope / Inter | `font-display`, `font-sans` |

Сетка: контейнер `page-container` (1440px, поля 20px / 50px), на десктопе 4 колонки с зазором 10px.
Брейкпоинты: мобильная вёрстка до 1024px (`lg`), промежуточная двухколоночная от 768px (`md`).

Текст из контента выводится через `typo()`: предлоги и союзы не остаются в конце строки, тире не начинает строку.

### Liquid Glass

Стекло — класс `.glass-material` в `globals.css`: псевдоэлемент `::before` размывает и тонирует фон
под элементом, `::after` рисует блики по кромке и свет под курсором; текст остаётся чётким.
Варианты задают переменные `--glass-tint`, `--glass-blur`, `--glass-depth`, `--glass-strength`:

| Класс | Где |
|---|---|
| `glass-material-hero` | панель «Проектирование, поставка, монтаж и сервис» |
| `glass-material-contacts` | капсула контактов (`ContactPill`) |
| `glass-material-form` | карточка формы заявки |
| `glass-material-blue` | плашки услуг, кнопка в мобильном меню |
| `glass-material-menu` | панель мобильного меню |

`LiquidGlassEnhancer` в Chromium строит для каждого `.glass-material` SVG-линзу по его размеру
(`src/lib/liquid-glass.ts`) и подключает её через `--glass-refraction`; в Safari и Firefox остаются
размытие, тонировка и блики. При «Уменьшить прозрачность» стекло становится плотным.

### Мобильное меню

`MobileMenu` — нативный `<dialog>`: фокус, Esc и блокировка прокрутки из коробки.
Стеклянная панель вырастает из кнопки-бургера, его линии складываются в крестик, пункты
появляются каскадом; закрытие — в обратную сторону (атрибут `data-closing`, анимации в `globals.css`).
Панель анимируется только через `transform`: `opacity`/`filter` у неё отключили бы размытие фона под стеклом.

## Контент

Все тексты главной лежат в `src/content/*.ts`. Их структура повторяет будущие коллекции CMS,
поэтому подключение CMS сводится к замене этих модулей на загрузку данных.

## Заявки

Форма отправляется Server Action'ом `submitLead`: заявка сохраняется в SQLite, уведомление ставится в очередь Telegram. Защита от спама — скрытое honeypot-поле и ограничение частоты. См. раздел «Мини-CRM в Telegram».

## SEO и документы

Публичный адрес сайта задаётся переменной `NEXT_PUBLIC_SITE_URL` (по умолчанию `https://vent-core.com`) при сборке. Он используется для canonical, Open Graph, robots.txt и sitemap.xml. Установите фактический HTTPS-адрес перед сборкой и настройте основной домен и перенаправление альтернативных адресов на сервере.

`/sitemap.xml` содержит главную страницу, галерею и статьи; `/robots.txt` указывает адрес карты сайта. При изменении статьи необязательное поле `updated` в её данных следует установить только на дату существенного обновления. Sitemap не подставляет время каждой сборки как дату изменения контента.

Для `/privacy` и `/terms` заполните `LEGAL_OPERATOR_NAME`, `LEGAL_OPERATOR_INN`, `LEGAL_OPERATOR_ADDRESS`, `LEGAL_OPERATOR_EMAIL` и проверьте содержание с учётом фактических процессов. Только после этого установите `LEGAL_DOCUMENTS_APPROVED=true` и пересоберите приложение. До подтверждения на страницах видна отметка черновика, они закрыты от индексирования и не включены в sitemap. Согласие, сроки хранения, передачу данных в Telegram и другие фактические процедуры необходимо отдельно проверить перед запуском.

После размещения сайта добавьте `/sitemap.xml` в Google Search Console и Яндекс Вебмастер. Карта помогает обнаружению страниц, но не гарантирует индексацию или позиции.

## Мини-CRM в Telegram

CRM рассчитана на один VPS с постоянным диском и Node.js **22.13 или новее**. Заявки сохраняются в SQLite; статусы, заметки, заказы и напоминания доступны только администраторам в личном чате с ботом. Отправка клиентских контактов в Telegram предусмотрена задачей; перед запуском заполните фактические реквизиты и политику конфиденциальности сайта.

### Подготовка

1. Скопируйте `.env.example` в `.env.local` для разработки или создайте серверный файл `/etc/ventcore/crm.env`. Закройте доступ к нему для посторонних (`chmod 600`). Секреты нельзя добавлять в Git, пересылать в чат или публиковать в логах.
2. Укажите `TELEGRAM_BOT_TOKEN` существующего бота. В `TELEGRAM_WEBHOOK_SECRET` и `CRM_CRON_SECRET` задайте **разные** случайные строки длиной не менее 32 символов; для webhook допустимы только латинские буквы, цифры, `_` и `-`. Пример генерации в своём терминале: `node -p "require('node:crypto').randomBytes(32).toString('hex')"`.
3. На VPS укажите `CRM_DB_PATH` как абсолютный путь на постоянном диске **вне папки приложения**, например `/var/lib/ventcore/crm.sqlite` (при выпуске новой версии папка приложения пересоздаётся, и база внутри неё пропала бы — в production сайт откажется стартовать с таким путём). Папка принадлежит пользователю сайта, права `700`; пример unit-файла с `StateDirectory` — `deploy/ventcore.service`. Не размещайте базу в публичных файлах или во временном слое контейнера. Как база защищена и как её восстановить — в разделе «Защита и восстановление базы» ниже.
4. Укажите `TELEGRAM_WEBHOOK_URL=https://ВАШ-ДОМЕН/api/telegram/webhook` и разверните сайт за HTTPS. Пока адреса и VPS нет, webhook и напоминания включить невозможно. Для установки webhook выполните на сервере `node --env-file=/etc/ventcore/crm.env scripts/setup-telegram-webhook.mjs`. Скрипт не перезаписывает другой существующий webhook без явного `--replace` и не удаляет ожидающие обновления.
5. Каждый администратор открывает личный чат с ботом и отправляет `/id`, чтобы узнать свой Telegram ID. Укажите эти ID через запятую в `TELEGRAM_ADMIN_IDS` и перезапустите сервер. Затем каждый администратор отправляет `/start` и видит меню. Бот не может отправлять уведомления администратору, который ещё не начал с ним личный чат.
6. Настройте минутный запуск `scripts/crm-tick.mjs` через systemd: примеры — `deploy/ventcore-crm-tick.service` и `.timer`. Замените пользователя, группу, путь проекта и Node.js на реальные значения сервера, подключите тот же `/etc/ventcore/crm.env`, затем установите и включите таймер. `CRM_INTERNAL_URL` должен указывать на локальный HTTP-адрес приложения; скрипт не отправляет секрет на внешний адрес. В reverse proxy запретите внешний доступ к `/api/internal/crm/tick`. Сервис и таймер проверяются через `systemctl status` и журнал systemd.
7. Для ограничения потока заявок используйте доверенный reverse proxy, который **перезаписывает** `X-Real-IP` адресом клиента, и только после этого включите `CRM_TRUST_PROXY=1`. Без этого действует общий лимит и нельзя надёжно отличить отдельных посетителей. Прямой доступ к порту приложения извне должен быть закрыт. Не доверяйте заголовку, который может подставить клиент.

Новая заявка и задачи отправки сохраняются одной транзакцией. При временной недоступности Telegram заявка остаётся в базе, а очередь повторяет отправку с увеличением интервала. При перезапуске восстановление происходит после следующего запуска таймера; возможен повтор уведомления, если Telegram принял сообщение непосредственно перед сбоем процесса. Проверяйте состояние таймера, доступность Telegram и резервные копии. SQLite здесь рассчитана на один сервер с локальным постоянным диском; для нескольких серверов нужна общая транзакционная база и отдельный механизм фоновых задач.

Клиент может отправить `/start` или `/request` в личном чате и оставить заявку по кнопке: имя, телефон, необязательное описание и подтверждение. Заявка попадает в ту же CRM, а в заметке сохраняются источник, Telegram ID и факт согласия. Незавершённые данные удаляются по истечении 30 минут при следующем обращении к боту. Не более пяти заявок с одного Telegram ID в час. Администратору доступны кнопки разделов и поиска; вернуться в меню можно командой `/crm` или `/start`. Для публикации необходимо подготовить действующую политику обработки персональных данных.

**Подписка на канал и связь с менеджером.** При `/start` клиент сначала видит приглашение подписаться на канал `@ventcoreblog` (кнопки «Подписаться на канал» и «Я подписался»); заявка и связь с менеджером открываются после подписки. Для проверки сделайте бота **администратором канала** (достаточно права «Просмотр участников»); при необходимости задайте канал в `TELEGRAM_CHANNEL_ID`. Подписка запоминается на 10 минут. Если проверить подписку не удалось (бот не админ, Telegram недоступен), клиента не блокируют, а в лог пишется предупреждение. Кнопка «Связаться с менеджером» после подтверждения согласия создаёт заявку без телефона и отправляет всем администраторам уведомление с кнопкой «Написать клиенту» (ссылка на username или `tg://user?id=…`); не более трёх запросов в час с одного Telegram ID.

### Защита и восстановление базы

Что делает код (`src/lib/crm/db.ts`, `src/lib/crm/backup.ts`):

- **Надёжная запись.** SQLite в режиме WAL с `synchronous=FULL`: подтверждённая заявка не теряется даже при внезапном отключении питания. При остановке сервера журнал дописывается в основной файл.
- **Проверка при каждом запуске.** `PRAGMA quick_check`. Если база повреждена, сервис сам поднимает её из новейшей исправной копии, а повреждённые файлы сохраняет рядом как `crm.sqlite.corrupt-…`. Если исправной копии нет — файл не трогается, а сервис отвечает ошибкой (Telegram повторит доставку), пустая база поверх повреждённой не создаётся.
- **Файл базы пропал** (диск пересоздан, случайное удаление), а копии остались — база поднимается из копии, а не создаётся пустой.
- **Резервные копии** создаёт таймер `crm-tick` (раз в минуту проверяет, не пора ли): по умолчанию **каждый час** (`CRM_BACKUP_INTERVAL_HOURS`, 1–168). Копия делается без остановки сайта, проверяется и только потом получает имя `crm-ГГГГММДД-ЧЧММСС-scheduled.sqlite`. Хранятся: все копии за 48 часов, затем по одной в сутки до 30 дней (это укладывается в срок уничтожения данных из политики конфиденциальности), плюс пять последних копий перед обновлением схемы. Права: папка `700`, файлы `600`. Папка — `CRM_BACKUP_DIR` или `backups/` рядом с базой.
- **Версия схемы** хранится в `PRAGMA user_version`; изменения схемы — только новыми миграциями в `db.ts` (выпущенные не редактируются). Перед миграцией существующей базы делается копия. База от более новой версии приложения не открывается — это защищает от порчи при откате версии.
- **Уборка.** Отправленные и отменённые сообщения очереди (в них имена и телефоны) удаляются через 14 дней.
- Сбой копирования не молчит: таймер `crm-tick` завершается с ошибкой, это видно в `systemctl status` и `journalctl`.

Чего код не может сделать сам — **копию на другом диске или сервере**. Копии в `/var/lib/ventcore/backups` лежат на том же диске, что и база: при поломке диска или потере сервера пропадут обе. Настройте вынос копий, например ежедневный `rclone sync /var/lib/ventcore/backups remote:ventcore-backups` или `rsync` на другой сервер (по cron или systemd-таймеру), и хотя бы раз в квартал проверяйте, что копия открывается: `node --env-file=/etc/ventcore/crm.env scripts/crm-db.mjs list`.

Утилита `scripts/crm-db.mjs` (запуск `node --env-file=/etc/ventcore/crm.env scripts/crm-db.mjs <команда>`):

| Команда | Что делает |
|---|---|
| `list` | список копий и проверка каждой |
| `check` | проверка целостности рабочей базы |
| `backup` | копия прямо сейчас — выполняйте перед выпуском новой версии |
| `restore <файл> --yes` | вернуть базу из копии |

**Восстановление базы вручную:** `systemctl stop ventcore` → `crm-db.mjs list` → `crm-db.mjs restore <файл> --yes` → `systemctl start ventcore`. Прежние файлы базы не удаляются, а сохраняются с суффиксом `.before-restore-…`. Заявки, пришедшие после времени копии, в восстановленной базе отсутствуют (при часовой копии — не более часа); их можно найти в сохранённых файлах или в уведомлениях Telegram.

### Возможности бота

- `/leads` — список заявок с переходом по страницам; `/search имя или телефон` — поиск.
- В карточке заявки: статусы «Новая», «Связались», «В работе», «Предложение», «Успешно», «Отказ»; заметки и история записей с переходом по страницам.
- К заявке можно добавить заказ с названием и необязательной суммой в рублях, а затем переключать его статус.
- Напоминание можно назначить через час, завтра в 10:00 или на свою дату. Формат: `ДД.ММ.ГГГГ ЧЧ:ММ | текст`; время всегда московское. `/reminders` показывает собственные активные напоминания и позволяет отменить их.
- `/orders` показывает последние заказы; `/cancel` отменяет текущий ввод.

До заполнения токена и списка администраторов форма сообщает об ошибке и не выдаёт ложное подтверждение. При сохранённой заявке и кратковременном сбое Telegram посетитель получает подтверждение, а уведомление остаётся в очереди. Удалять администраторов можно через конфигурацию с перезапуском; их ещё не отправленные уведомления отменяются при обработке очереди.
